# 残高復元と取り込みのリファクタ課題

[English](REFACTOR.md) | 日本語

2026-09-26時点の設計方針と受入条件。残高解析やGMOパーサーの分離など一部は実装済みですが、抽象基底クラス・Merrill/GMO派生クラス・ローカル登録配列も実装済みです。金融機関から独立した保存モデルへの全面移行は未実装です。現在の構成と追加手順は [BROKER_ADAPTERS](BROKER_ADAPTERS.ja.md)、実装履歴は [HANDOFF](HANDOFF.ja.md) を参照してください。

## 1. 直近資料から暦年の期初・期末残高を復元

基本入力は Activity、直近 Holdings、直近 Portfolio Summary の3種類。
過年度の Portfolio Summary の取得は要求しない。取得ロット明細・権利確定明細は取得費や差異の照合が必要な場合の補助資料とする。
過去資料の OCR・根拠付き手入力は別途拡張する。

- Holdings の口座・銘柄別数量、Portfolio Summary の口座・通貨別現金等を、資料の基準日時付きの観測残高として保存する。同じ残高の重複計上を避け、Cash / Money Accounts / Investments / Net Value の内訳と合計を区別する。
- 両資料は原則同一の COB 日を使う。Realtime の未決済残高と確定残高を混ぜない。基準日が異なる場合は別の基準として必要な期間を算出する。
- 対象年の1月1日開始時点から各資料の基準日時までの Activity が必要。表示対象年の取引だけでは、翌年取得した残高から逆算できない。
- 期初残高 = 基準残高 − 期初から基準までの符号付き増減。期末残高 = 期初残高 + 当年の増減。数量と原通貨残高を復元し、各評価日の価格・為替による評価は別処理にする。株式分割等は逆変換が必要で、単純加減算の対象にしない。
- 現金には売買、入出金、配当、源泉徴収、手数料、振替を反映する。元の Amount を無条件に全部足す実装にしない。自己口座間振替を所得として扱わない。
- 株式の権利確定日・入庫日、売買の約定日・受渡日を保存し、残高増減日と所得計上日を分離する。資料がどの残高を表すかに応じて採用日を決める。
- 資料にない銘柄の残高をゼロとするには、口座全体の完全な Holdings である確認が必要。全売却済み銘柄も Activity から復元対象にする。
- ファイル内の最古・最新取引日から完全な収録期間を断定しない。収録期間、未対応イベント、未解決重複、負の数量などの問題を表示する。
- 画面は暦年ごとの期初、当年増減、期末を口座・資産別に表示。観測残高と逆算残高を区別し、元資料と計算内訳に戻れる。年末表示には12月31日時点の残高を利用する。
- 現金残高と Activity 合計が一致しないだけでは矛盾ではない。開始残高がゼロという根拠はない。逆算と順算で元に戻ることは計算の検証であって、履歴完全性の独立した証明ではない。
- 残高の復元では過年度の取得費は復元できない。開始数量と取得費・取得日・その根拠を分け、不明取得費は未確認のまま引き継ぐ。

受入確認: 架空資料で前年期末/翌年期初の一致、年越し受渡、基準日違い、重複、資料欠落、全売却済み銘柄、現金振替、分割、旧保存ファイル互換を確認する。

## 2. 会社ごとに差し替え可能な取り込み

- Merrill固有列・説明の解析は `src/brokers/merrill-activity.ts` へ分離済み。残る会社固有の保存スキーマや共通計算内の原列依存を整理する。
- アダプターは資料判別、形式バージョン、原資料保持、正規化、未対応行の報告を担当する。ファイル名だけで資料種類・収録期間を決めない。
- 共通側は口座、資産、取引、残高スナップショット、収録期間、出典、レビュー、保存を担当する。
- 曖昧な資料判別は確認を求める。未知の取引を黙って捨てない。自動判定・利用者確認の根拠を保持する。
- 初期実装はローカルのアダプター登録方式とし、外部コードを動的取得・実行する仕組みは不要。
- 参考計算・相場取得は会社別パーサーから独立させ、保存移行では元資料とレビューを維持する。

## 3. 暗号資産を扱える共通記録

- 資産種別（株式、法定通貨、暗号資産等）と事業者を別概念にする。NYSE/NASDAQ とティッカーを全資産の必須識別子にしない。
- 暗号資産はネットワーク・コントラクト等も識別に利用できる設計にし、同じ略称の別資産を混同しない。口座に加えてウォレットも扱えるようにする。
- 交換は出庫資産・入庫資産・手数料資産の複数の増減として保持する。日時・タイムゾーン・小数精度を保持する。
- 自己口座/ウォレット間移動の対応付けと取得履歴の引き継ぎを用意する。移動先の市場価格で取得費をリセットしない。相手方不明の入庫では取得費未確認を引き継ぐ。
- 保管先別残高と、評価ルール上の取得費集計単位は分離する。会社別に取得費を閉じる実装にしない。
- 国内外を問わず、既存保有分の取得費は開始時残高だけでは分からない。過年度資料または根拠付き開始取得費を受け入れる。
- 当面は資料整理・残高・取得履歴の保持まで。
- 評価方式はパーサーから分離し、採用した方法と根拠を記録する。




実装順序: 共通の残高/出典モデルとMerrillアダプター分離 → 3資料取り込みと暦年残高表示 → 別事業者/暗号資産のアダプター追加。
