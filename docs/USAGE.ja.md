# 操作と参考計算の詳細

[English](USAGE.md) | 日本語

初回の起動とMerrillの取り込み手順は [README](../README.ja.md) を参照してください。

## できること

- Add CSV から Merrill Activity / Holdings / Portfolio Summary を列構成で自動判定。Broker で自動判定または Merrill を指定できます。
- Holdings / Portfolio は日付付き・Realtime の両形式に対応。取り込み後は Sources & balances に移動し、基準日・口座別の数量、現金、Money Accounts、投資評価額、純資産と原行を表示します。資料ごとのスナップショットを保持し、この資料表示では合算しません。残高も記録の保存・復元に含まれます。
- Merrill CSV の複数ファイル取り込み、ドラッグ＆ドロップ、Trade Date からの年表示、検索、原資料の明細表示。
- 欠損とゼロの区別、括弧付き負数・カンマ付き数値・複数の日付・CB の保持。数値は精度を落とさない文字列で保存。
- 同一ファイルの再取り込み防止と、一致する行の重複候補表示。除外と取り消し、別取引として保持する操作。
- 銘柄の正式名称・ティッカー・取引所を示す候補検索。現在の一覧でティッカーが一意に完全一致する場合は自動対応付けし、手動で変更可能。
- 資料の収録期間と根拠、開始残高と未確認の取得費を記録。
- JSON ファイルへの保存・復元。元の CSV 行も保存するため、保存先は個人資料として管理してください。

読み込んだ取引資料はメモリ内で処理し、サーバー・外部 API・ブラウザの永続ストレージには送信・保存しません。
ページを閉じる前に「保存する」を選んでください。再開時は「記録を開く」で復元します。
開発中の自動再読み込みは無効です。コード変更を確認する際は、保存後に手動で再読み込みしてください。

## 表示言語

初回は英語で表示します。サイドバーの **Language** で **English / 日本語** を切り替えられます。
選択した言語と株式・暗号資産ブロックの開閉設定だけを `localStorage` に記憶します。ブラウザの言語から自動選択はしません。
切り替え時に記録・検索条件・入力途中のフォームを保持し、原資料の説明や利用者のメモは翻訳しません。
表示言語を変えても集計方法は変わりません。

翻訳定義は `src/i18n.ts` にまとめています。英語のキーを基準に日本語の不足を型検査し、
キーと差し込み項目の一致をテストします。追加言語は同じキーの辞書、Locale 型、言語選択肢を追加して対応します。
確認事項は言語に依存しないコードとして扱い、以前の保存ファイルは原資料から再構築して読み込みます。

## 銘柄一覧の準備

`npm run catalog` は Nasdaq Trader の公開銘柄一覧から NYSE / NASDAQ の銘柄を取得し、
取得日時・出典とともに `public/instruments.json` へ保存します。個人資料を読み取る処理はありません。
検索はこの静的一覧に対してブラウザ内で行い、入力文字列を外部に送りません。
一覧を更新する場合も同じコマンドを実行します。

出典と形式: [Nasdaq Trader Symbol Directory Definitions](https://www.nasdaqtrader.com/Trader.aspx?id=SymbolDirDefs)。
これは現在の銘柄一覧で、過去の上場廃止・社名変更・ティッカー再利用は別途確認が必要です。
取得ファイルは Git 対象外です。再配布条件は未確認のため、配布物に含める前に確認してください。
`npm run build` はローカルの銘柄一覧も `dist/` にコピーします。銘柄一覧とdistはローカル専用・Git対象外としてください。アプリはソースで配布します。
一覧の取得前でも CSV の取り込み・保存と架空銘柄のデモは利用できます。

## 日次株価

**Market data** からキー不要の Stooq CSV の取得リンクを作成し、ダウンロードした CSV を取り込めます。
銘柄ごとの CSV 日付から From / To を提案し、次回はキャッシュにない期間を案内します。
重複日をマージし、値の改訂と元の出典を保持します。キャッシュは記録保存に含まれ、株価だけの JSON にも書き出せます。
CB / Price / 同日終値を参考単価の候補として比較・選択し、出典とともに記録へ保存します。
配当・源泉徴収 は一律レビューを外し、欠損・符号・重複などに確認を絞っています。

自動収集は `npm run prices -- --help` を参照。この環境では Stooq が HTTP 403 を返し、
実株価の自動取得は未成功です。調整方法・再配布条件も未確認です。
操作・保存形式・制限は [株価データの説明](MARKET_DATA.ja.md) を参照してください。

## USD の年次集計

Overview の年ボタンを選ぶと、Yearly totals / gain に vest 評価額・実現損益・売却代金・配当・源泉徴収を分けて表示します。
vest の評価額 と、株式の譲渡損益・配当を分けます。譲渡損益と配当も別項目とし、全区分の合算・自動通算は行いません。
「銘柄別の内訳」で各銘柄の vest・損益・配当・売却代金・源泉徴収を展開し、元取引の明細へ移動できます。確認済みの同じ取引所・ティッカーはまとめ、未解決の銘柄表記は別に保持します。
現時点では Trade Date による暫定分類です。検索文字列では年次合計を変えません。

- Vest 評価額は数量×一覧の参考単価。採用済み単価を優先し、未採用なら同日終値、なければ CB / Price の候補を使用。未レビュー件数を明示します。
- 売却の Details で手取総額・売却分の取得費総額（USD）・根拠を記録すると、差額を年間損益に反映します。手入力がなければ Activity 内の取得分を平均化して損益を計算します。
- Source amount は原資料の値のままです。一覧は Amount 列に暫定 vest 評価額、売却代金、配当・源泉徴収の原金額を表示します。単価・終値・出典は Review / 明細で確認します。実現損益は年次集計に分けて表示します。
- 欠損・未解決の重複は合計から除き、小計と未確認件数を表示。未知の値をゼロにしません。日付不明は年に割り当てません。
- 参考為替換算に対応。資料の完全な収録期間も保証する集計ではありません。

## ドル・円

Market data 内の **USD / JPY** にまとめています。

```sh
npm run fx
```

FRED の公開 CSV（DEXJPUS、キー不要）を取得し、出典・日時・ハッシュ付きで `public/fx.json` に保存します。
手元の FRED CSV は `npm run fx -- --csv /path/to/file.csv` でも取り込めます。
Market data → USD / JPY → **Load local FX cache** を押し、Overview の **Currency** を JPY に切り替えると、行と年次集計を参考換算します。
CSV / JSON の画面取り込み・為替キャッシュ書き出しにも対応します。記録の Save に為替データを含みます。

出典は [FRED DEXJPUS](https://fred.stlouisfed.org/series/DEXJPUS)。1 USD あたりの円で、NY 正午買いレートです。TTM ではありません。
Vest は LAPSE DATE（なければ Trade Date）、配当・源泉徴収・売却手取額は Trade Date の同日レートを使用。
休日・欠損日は次にレートがある日で補完し、明細に対象日と採用したレート日を表示します。将来側のレートも未取得なら未確認です。年の分類は Trade Date のままです。
円の売却損益は換算手取額−売却分の円建て取得費です。取り込み済みの取得履歴から参考計算し、Detailsで手入力できます。不足は未確認として表示します。
USD 損益全体を売却日の為替で乗算しません。

## 年末・最新ポートフォリオ

Overview の All と当年は取り込んだ最新残高、過去年は12月31日時点のポートフォリオを選択中の USD / JPY で表示します。年ボタンは残高のみ取り込んだ場合も表示します。最新の純資産は Portfolio Summary の報告値で、株式・現金・Money Accounts の内訳とは重複加算しません。

過去年は後日の COB 残高から受渡日ベースの対応済み Activity を逆算します。資料収録期間が未確認の場合は履歴完全性を条件とする暫定値です。欠損日・未解決重複・未対応の増減・負の逆算株数では値を未確認にします。過去の Money Accounts はスイープ等の解析が未対応のため未確認です。

年末評価は確認済み銘柄の株価キャッシュから評価日以前の取得済みデータの最終終値を使用し、実際の価格日を表示します。過去の株価がない場合は数量のみ表示。無調整と未確認の相場評価は暫定です。ポートフォリオも通貨切替に連動します。JPY は残高評価日以前の最終 FRED レートで参考換算し、採用日を明細に表示します。為替未取得は未確認です。状態欄から基準資料・計算に使用した取引を確認できます。

画面は年・通貨の共通選択の下に、取引集計 → ポートフォリオ → 取引一覧を独立したブロックとして表示します。ファイル数・取引件数・要確認件数は上部の小さな補助表示です。取引検索は一覧のみを絞り込みます。

## 売却損益と取得費の修正

取得費の手入力がない売却は、同じ口座・銘柄の売却日以前の Activity の取得分を平均化して計算します。高い単価からの割り当てはしません。取得は現在 RSU vest に対応し、未対応の売買・移管等を無条件に計算へ含めません。表示通貨が JPY の場合は取得ごとの日付で円換算してから平均化します。売却日の USD 損益を一括円換算しません。

不足数量だけは初期ポートフォリオ時点の取得済み最終株価で補い、その売却全体を「参考売却損益（取得費未確認）」として赤字で別集計します。基準日は明示した開始残高の日付を優先し、次にHoldingsから推定した最古Activity年の前年末Openingを使います。それらがなければ最古Activity日 / 記録した収録開始日を使用します。採用した基準日・価格日・為替・平均単価・数量・計算式を明細に表示します。価格等がなければ未確認。損失そのものを警告色の理由にはしません。

Details では取得費総額・平均取得単価・取得履歴の3通りで修正できます。USD / JPY を選び、売却手取額は USD で記録します。メモ・資料添付は必須ではなく「手入力・資料未添付」として保持します。履歴はこの売却に割り当てる取得分を日付・数量・取得費総額で入力して平均化します。総額・平均単価は入力通貨の取得費としてのみ使用し、USD 履歴なら取得日ごとに JPY へ参考換算できます。Clear で自動計算に戻ります。

これは取り込んだ範囲による参考計算です。口座をまたぐ完全な取得費の算定、Activity より前の取得履歴の補完、同日内の約定順の確定は行いません。同日は取得を先に扱い、平均割当額は小数12桁で丸め、残存取得費との差額を維持します。

## GMO Coinの暗号資産CSV

「CSVを追加」でGMO Coinの取引履歴を自動判定します。BrokerでGMO Coinの指定も可能です。BTC預入・販売所売買・円入出金等を株式とは別ブロックに表示し、年別の数量増減・JPY受渡額・手数料原欄を保存します。ヘッダーのみのCSVにも対応。預入は取得費未確認の移動として扱います。

売却は取得費総額をJPYで手入力できます。未入力なら取り込み済み取得履歴を使用し、履歴不足の場合に売却価額の5%を暫定取得費に使います。[対応形式と制限](GMO.ja.md)、[架空サンプル](../data/sample-gmo/README.ja.md)を参照してください。

Overview / Reviewでは株式・暗号資産を個別に折りたためます。閉じても損益・株式評価額・要確認件数を見出しに保持します。年の選択はOverviewで共通、暗号資産の取得費・受渡額は原通貨JPYです。取得費は独立した列で、対象数量と出典（CSV・手入力・移動平均・5%暫定）を表示します。

## 取引一覧のページ分割

株式・暗号資産の取引一覧はそれぞれ50件ずつ表示し、「前へ / 次へ」で移動します。Reviewの株式単価・重複候補・確認事項と暗号資産一覧もページ分割します。ページ数と全件中の表示範囲を表示し、資産ごとに独立して移動できます。

年・画面・検索条件の変更、新規取り込み・記録読み込みでは先頭ページへ戻ります。検索は全株式取引を対象にしてからページ分割します。年次集計・ポートフォリオ・要確認件数・記録保存はページに関係なく全対象データを使います。ページ分割は表示件数を制限するもので、取り込みや全件計算の処理時間・メモリ量を一定にする機能ではありません。

## 保存ファイルの識別子

表示名はAnnumAequitas、機械用の名前は `annum-aequitas` です。記録JSONは `format: "annum-aequitas"` と `version: 1`、株価JSONは `annum-aequitas-prices`、為替JSONは `annum-aequitas-fx` を使います。旧識別子の保存ファイルはそのままでは読み込めません。今回の改名ではトップレベルのformatだけを新識別子へ変更し、他の内容は保持します。

ダウンロード名、npm名、CI artifact、同意Cookie・表示設定の保存キーも `annum-aequitas` に統一しています。同意と表示設定は新しい名前空間で保存されるため、初回は再設定になります。
